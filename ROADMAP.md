## Roadmap: Event-Aware Scenario Forecasting (v2, `scenario-forecasting` branch)

### The problem this solves

The current model (`master`) forecasts spending as a pure function of time. For countries with smooth, stable trends, this is sound. For countries whose recent history is dominated by an exceptional event, it isn't: a trend-based model has no concept of "this spike is a war, not a permanent trajectory," so it extrapolates the recent slope indefinitely. Concretely, forecasting Ukraine 15 years out currently produces spending above 100% of GDP, a number with no real-world meaning. This is a known, general limitation of trend-only forecasting, not a bug specific to this implementation, but it's worth solving properly rather than just capping the output.

### Why not just add more variables directly

The intuitive fix, "factor in GDP, conflict, neighboring instability, etc.," runs into two real constraints:

1. Each of the 31 current models is trained on only ~46 yearly data points (one country's own history). Adding several input variables to a dataset that small risks overfitting rather than improving the model, the same failure mode discussed in the original Iris project.
2. Forecasting forward requires knowing *future* values of any added inputs (future GDP, future conflict status), not just future dates. Those are themselves unknown, so this isn't a bolt-on fix; it changes what "forecasting" means.

The resolution is scenario-based forecasting: rather than one blind extrapolation, produce a small number of named, clearly-labeled forecasts, each conditional on an explicit assumption about the future (e.g., "conflict continues" vs. "conflict resolves within 3 years"). This is standard practice in real economic and policy forecasting, and it directly fixes the Ukraine problem: different assumptions produce different, individually sensible numbers, instead of one number pretending to be certain.

### Planned pipeline

**1. Event data — GDELT, via BigQuery**
Pull and aggregate GDELT's event data to yearly, per-country summaries for the existing 31 countries, using BigQuery's SQL interface rather than parsing raw event files directly. Decided date range: **1980-2025**, matching the existing SIPRI window exactly, for a clean join on country + year with no gaps to explain (GDELT itself covers back to 1979, but there's no reason to pull the extra year). GDELT's built-in Goldstein scale (an existing intensity/tone score) is a useful starting signal before any custom modeling is layered on top. Google Cloud's free tier (1 TB of query processing/month) comfortably covers this, since the result is aggregated down to a small summary table, not a raw bulk pull.

**Finding (2026-07-22), after pulling and inspecting the real aggregated data:** average Goldstein score at yearly granularity is a weaker signal than expected — averaging across hundreds of thousands of routine events per country-year dilutes real intensity spikes (Ukraine's 2022 `avg_goldstein` is actually *higher*, i.e. less negative, than its 2018 value). Event/mention **volume** is the stronger signal, but only once normalized: GDELT's own historical source coverage grows roughly 17x between 2006 and 2016 across all 31 countries combined, a documented artifact of event databases backfilling more/newer sources over time, not a real-world trend, so raw mention counts (or a same-country trailing average of raw counts) are confounded by this shared ramp. Normalizing each country-year's mentions as a **share of that year's combined total across all 31 countries** cancels the shared trend and cleanly surfaces real events: Ukraine 2022 is a **12x outlier** relative to its own trailing baseline share — by far the largest in the dataset — while Türkiye's peak correctly lands on 2016 (the real coup attempt) at a more modest 1.6x, and Egypt 2011 (Arab Spring, 3.0x) and Israel 2023 (Gaza war onset, 3.1x) also surface as real, independently-recognizable events at smaller magnitudes. This share-normalized volume feature, not raw Goldstein/tone averages alone, is the primary signal the embeddings step below uses.

**2. Embeddings**
Convert each country-year's aggregated event summary into a vector embedding, so country-years can be compared by underlying similarity rather than exact wording. Per the finding above, the embedded representation must include share-normalized mention volume relative to that country's own trailing baseline (the stronger signal) alongside `avg_goldstein` and `avg_tone` — not raw Goldstein/tone averages alone, which understate real spikes. Using `sentence-transformers` (Hugging Face), run locally — no API cost, and the volume here (roughly one embedding per country-year, ~1,400 total) is small enough that a local model is both sufficient and the more practical choice regardless of budget.

**Finding (2026-07-22), from a nearest-neighbor sanity check before trusting the embeddings for clustering:** the first version of the embedded text led with `"{Country} in {Year}:"`. That made country identity dominate similarity almost completely — Ukraine 2022's nearest neighbors were nearly all *other Ukraine years*, not other volatile country-years elsewhere, which would have caused step 3's clustering to rediscover "31 country clusters" instead of the cross-country event-type groupings this whole approach is for. Fix: Country and Year are excluded from the embedded text entirely and kept only as separate metadata columns alongside the embedding. Re-checked after the fix: Ukraine 2022's nearest neighbors are now Ukraine 2014, Russia 2022, Israel 2023/2024, and Egypt 2011 — genuinely cross-country, all negative-tone volume spikes. Norway 2022 clusters with "typical baseline" years from Canada, Germany, Vietnam, Argentina, Sweden, and Colombia. Egypt 2011 clusters with *other positive-tone* spikes (Korea 1987, India 1984, Nigeria 2000).

**Follow-up finding (2026-07-22), after pulling real event samples for Korea 1987 and India 1984 to verify that "positive-tone spike" grouping wasn't coincidental:** both are real, and both are violent, not peaceful. Korea 1987's top events by mention volume are Seoul student protesters vs. riot police (EventCode 190/"FIGHT", GoldsteinScale repeatedly -10.0) clustered April-September 1987 — the real June Democratic Uprising against military rule. India 1984's top events are Sikh actors vs. paramilitary police in Amritsar/Punjab (the Operation Blue Star era) and Hindu-Muslim communal violence in Bombay, with Zail Singh, Indira Gandhi, and Rajiv Gandhi as real actors — one of the most violent years in modern Indian history, not a peaceful transition. The original speculation that this cluster represented "elections or diplomatic events" was wrong. What actually distinguishes it: nearly every one of these maximally-conflictual events (GoldsteinScale -10.0) still carries a **positive** AvgTone (1.9 to 11.7) - a real, documented divergence in GDELT between Goldstein (conflict/cooperation intensity) and AvgTone (lexical sentiment of the covering articles), not a data error. The actual pattern separating this cluster from Ukraine's: **domestic civil unrest / protest / communal violence** (positive-toned press coverage despite real violence) vs. Ukraine's **sustained interstate war** (uniformly negative-toned coverage) - both are real, both are volatile, but they're categorically different kinds of events, which is exactly the kind of distinction step 4's LLM interpretation needs to be able to draw out.

**3. Clustering**
Group country-years by embedding similarity (e.g., k-means, via scikit-learn — already a project dependency), surfacing natural groupings — such as a cluster containing Ukraine 2022+ alongside other historically volatile country-years — without predefining categories.

**Finding (2026-07-22):** two real bugs were caught and fixed while building the k-means input, both by inspecting actual cluster membership rather than trusting silhouette score alone:
1. An early version's "no prior-year baseline yet" placeholder text was identical across every country's first ~3 years regardless of their actual tone/Goldstein values, so k-means grouped all 93 of them together by that shared *sentence*, not by any real event characteristic — a pure artifact, not a category. Fixing the placeholder text wasn't enough on its own: even after removing it, rows that simply *omitted* the volume clause were still structurally distinct (shorter, starting with "Average event tone...") and kept clustering together by that shape. The actual fix: minimize how many rows lack a computed spike ratio at all (trailing window `min_periods` reduced from 3 to 1, cutting 93 affected rows down to 31 - the genuinely unavoidable true-first-year-per-country case), and default those remaining 31 to `spike_ratio=1.0` ("assume typical") so every row's sentence has the same shape.
2. With that fixed, k=4 has by far the best silhouette score (0.51 vs. ~0.25-0.29 for k=5-9) and produces four sensible, evidence-checked groups: 1,006 "typical, positive-tone" years and 324 "typical, negative-tone" years, each **100% tone-pure**; 78 "elevated" years (88% positive-tone); and 18 "large spike" years (78% positive-tone, 22% negative). That last, smallest cluster is where Ukraine 2022 lands — alongside Russia 2022 and Israel 2023/2024 (negative-tone, the interstate-war pattern) *and* Korea 1987/India 1984/Egypt 2011/Argentina 1982 (positive-tone, the civil-unrest pattern from the finding above) in the same 18-member group. Raising k to 6 or 7 doesn't split it further - the extra clusters subdivide the two large "typical" groups instead, leaving this same 18-member group intact. So step 4's LLM interpretation needs to be able to tell interstate war apart from civil unrest *within* a single cluster's sample, not just assign one label per cluster - it can't assume every cluster is internally homogeneous.

**4. Interpretation (LLM)**
Two distinct uses, deliberately kept separate after finding that cluster membership doesn't reliably imply category homogeneity (see the clustering finding above) — they have very different tolerances for a wrong label:

- **As a regressor input (feeds step 5, every country-year):** cluster-inherited labels are fine. An LLM reviews a sample from each k-means cluster (from step 3) and assigns it one of the four categories; every member inherits it. An occasional mislabeled quiet year barely moves a fitted coefficient, and hand-labeling all 1,426 rows individually isn't tractable anyway.
- **As the trigger for automated scenario construction (feeds step 6, only `calculate_volatility`-flagged countries):** cluster-inherited labels are **not** used here. Each flagged country's own anomalous year(s) get individual LLM review, using that country's own description/samples directly — never whatever label its cluster happened to get. Only a handful of countries ever cross the volatility threshold, so individual review is cheap and tractable with a local model. This split matters because the cluster that would matter most for this decision isn't type-pure: at k=3 sub-clustering, Ukraine 2022 itself didn't land with its real type-peers (Russia 2022, Israel 2023/2024) — it grouped with Argentina 1982 and Ukraine 1986 by magnitude instead. A wrong regressor coefficient is a minor cost; a wrong scenario template automatically applied to a real country is not.

Categories: **conflict, currency instability, policy shift, stable**. Run locally via Ollama with Mistral 7B (confirmed installed and working, model storage on `D:` to avoid `C:` drive constraints) — free, no API cost. Paid API (Claude/OpenAI) remains a fallback if local labeling accuracy doesn't hold up.

**Required branch, not optional:** if a country is flagged by `calculate_volatility` but its GDELT signal shows no corresponding elevation, route to an explicit **"undetermined by GDELT — needs manual classification"** state. This must never silently default to "stable," which would incorrectly suppress scenario treatment for a country `calculate_volatility` already says needs it.

**Validation status of the four categories (2026-07-22), checked against real data before trusting any of them for automation:**
- **Conflict — confirmed present.** Ukraine 2022: `spike_ratio` 12.0x (the dataset's largest by far), negative tone, real invasion-period events.
- **Currency instability — confirmed absent.** Türkiye 2018: `spike_ratio` 0.77 — actually *below* its own trailing baseline. No GDELT event-volume signal at all; a true data absence, not a labeling gap. Routes to "undetermined by GDELT."
- **Policy shift — a real signal exists, but the current features don't capture it.** Germany's 2022 Zeitenwende (a real, major, documented defense-policy reversal — €100B special fund, reversing a 77-year policy against sending weapons to conflict zones) also shows no aggregate `spike_ratio` signal (never exceeds ~1.05 across 2018-2025). But pulling real events shows the Zeitenwende genuinely is there: NAVY/FRIGATE deployment events and Germany "providing aid" (EventCode 070, GoldsteinScale +7.0) cluster right at Feb 25-26 2022 — the Zeitenwende speech was Feb 27 — and cooperation events located at Ramstein appear Apr 25 / May 22 / Jun 25 2022, matching the real Ukraine Defense Contact Group ("Ramstein format") that began convening there in April 2022. Unlike Türkiye, this is not a data absence — it's a detection-methodology gap: Germany's baseline event volume is already enormous (see the earlier Canada/Australia media-coverage-bias note), and diplomatic/aid-provision events (Goldstein *positive* — cooperation, not conflict) generate lower relative volume than active fighting even when the underlying policy shift is major. Under the *current* feature set, a policy-shift country would still route to "undetermined by GDELT" — not because nothing happened, but because `spike_ratio`/`avg_goldstein`/`avg_tone` aren't sensitive to this category's actual signature (positive-Goldstein cooperation/aid events, not volume spikes). A future refinement — e.g. tracking QuadClass 1/2 (verbal/material cooperation) events specifically, rather than total volume — could plausibly close this gap. Not attempted in this phase; there is currently no usable "policy shift" template (see step 6).
- **Stable — the default/majority case**, not separately validated; there's nothing to verify beyond the absence of the other three.

**5. Feed labels into the existing models**
Every country-year inherits its cluster's label. This becomes a new regressor, added to Prophet via `add_regressor()` (a supported, standard Prophet feature, not a custom hack), alongside the existing time-based fit.

**Finding (2026-07-22), from a Ukraine-specific proof of concept before building this out for all flagged countries (`backend/test_regressor_ukraine.py`, uncommitted/in-progress):** deliberately simplified to wire `spike_ratio` directly into Prophet as the regressor (not a cluster/LLM category label yet) - the goal was to validate the *mechanism* first with the cleanest, least ambiguous signal available. Two questions tested, both against Ukraine's already-selected `changepoint_prior_scale=0.8`:

- *Does it improve historical fit?* Chronological backtest (train <=2015, test 2016-2025, matching `evaluate_country`'s existing discipline exactly - baseline MAE of 0.12250 matches the recorded `model_selection_log.json` value almost exactly, confirming the replication is faithful). Adding the regressor improved MAE by only **0.4%** (0.12250 -> 0.12197) - negligible. For 2022 itself (`spike_ratio`=12.0, actual spending 25.6%), the regressor-augmented prediction (3.67%) was barely different from baseline (3.82%) and actually moved slightly further from the true value. Root cause: the regressor's coefficient is learned entirely from the training window (1980-2015), which is pre-war and contains no precedent for "high `spike_ratio` co-occurring with a large spending jump" - the one real example (2022) falls entirely in the held-out test period, so there's nothing for Prophet to learn the relationship from during fitting.
- *Does it change the forward forecast under different future assumptions?* Retrained on the full 1980-2025 range, forecast 15 years out under two very different assumed future `spike_ratio` values: holding at the literal last-observed value (2025 = 1.03) versus the post-invasion (2022-2025) average (3.88, ~4x higher). The two scenarios differ from baseline and from each other by roughly **1 percentage point at 2040** - both still cross 100% of GDP by 2037, same as baseline. The regressor does not bound the extrapolation. Root cause: Ukraine's `changepoint_prior_scale=0.8` (high trend flexibility, already selected because it fit best *without* any regressor) means Prophet's own changepoint mechanism already absorbs the 2022 shift directly into the trend line; once absorbed, that new slope keeps extrapolating forward regardless of the regressor. The regressor and Prophet's native trend flexibility are competing to explain the same jump, and the trend - already tuned to do exactly that - wins.
- A related, earlier data point now reads as directly relevant here: `spike_ratio` reverts to near its own baseline (2025 = 1.03) even though real 2025 spending is still 39.6% of GDP (see the volume finding in step 1's follow-ups). `spike_ratio` detects escalation *moments*, not sustained *state* - a structural limitation for representing "conflict continues at current intensity" as a held-constant future value, independent of the changepoint issue above.

**Conclusion (round 1): the mechanism is correctly implemented (verified against the known baseline MAE) but, as tested, does not solve the extrapolation problem.** Three directions identified: (1) lower `changepoint_prior_scale`, (2) add a logistic growth cap, (3) try a binary conflict-active flag instead of continuous `spike_ratio`.

**Round 2 (2026-07-23), `backend/test_regressor_ukraine_v2.py`: growth cap + binary conflict flag tested together**, per the decision to skip directly to (2)+(3) rather than trying all three in isolation - `changepoint_prior_scale` stays at 0.8 throughout, to isolate the effect of the two changes actually being adopted.

- **Growth cap (`growth="logistic"`, `cap=0.50`):** cap value is a stated judgment call, not derived from data. Two components: (1) an empirical floor - it must exceed Ukraine's actual 2025 value (39.6% of GDP, still rising), which is a real, verified number from `cleaned_data.csv`; (2) a historical-precedent ceiling. **Correction (2026-07-23): the historical-precedent part was originally asserted from general knowledge, not verified, at the time this test was written - a lapse against this project's own standard of checking claims against real data rather than memory.** Checked now via web search: UK defence spending peaked around 46-52% of GDP in 1945 (sources vary by methodology - `ukpublicspending.co.uk` gives just over 52%, others give 46.4%), with WWI's peak slightly lower (~45-47%). 50% sits squarely inside that real range, so the chosen value holds up, but the earlier presentation of it as an already-checked fact did not - it happened to be correct, not because it was verified at the time.
- **Binary `conflict_active` flag:** 1 for 2022+ (the full-scale invasion), 0 before - sourced from known history, not thresholded from GDELT volume. Thresholding `spike_ratio` was considered and rejected: `spike_ratio` itself decays back toward baseline by 2025 regardless of where a threshold is drawn (see the step 1 finding above), so it would inherit the same "detects the moment, not the sustained state" problem the flag is meant to fix. The 2014 Donbas/Crimea period is treated as flag=0: real spending moved only from ~2.4% to ~3.8% GDP through that period, not distinguishable from year-to-year noise, versus the unambiguous 2021=3.4% -> 2022=25.6% regime shift.

**A latent bug found and fixed along the way, worth its own line: Prophet's default `yearly_seasonality` is a meaningless artifact on this data.** Every country-year is already a single yearly aggregate - there's no sub-year signal for a yearly seasonal term to model. With the growth cap in place, this stopped being harmless noise: it added a spurious +/-2pp wiggle on top of the logistic trend, enough to push forecasts visibly *above* the cap in some scenarios, which defeats the entire point of adding one. Fixed for this test via `yearly_seasonality=False`. **This is not a Ukraine-specific or regressor-specific issue - `train.py` never disables it either, so it is presently live in the yhat of all 31 production models**, just masked there because trend dominates the signal in every case that isn't up against a cap. Filed as a separate follow-up (see "Next actual step" below), not fixed in `train.py` as part of this change.

**Fixed in production (2026-07-24):** `yearly_seasonality=False` added to every Prophet construction in `train.py` - not just the two places already fixed (the capped-country branch, and `scenario_pipeline.py`'s own models), but `evaluate_country()` itself, which is used for model selection (deciding linear vs. Prophet, and which `changepoint_prior_scale` wins), not just the final model. That distinction mattered in practice: retraining with the fix changed the chosen model or scale for **10 of the 31 countries** - Poland, Saudi Arabia, Australia, and Norway flipped from linear regression to Prophet outright (the seasonality noise had been inflating Prophet's backtest MAE enough to lose to linear before), and Brazil, Colombia, United Kingdom, Germany, Korea, and Egypt kept Prophet but selected a different `changepoint_prior_scale`. This is a materially bigger effect than the cosmetic smoothing the bug was originally found for - fixing only the final model and leaving `evaluate_country()` unfixed would have meant selecting a model/scale under stale, noise-corrupted MAE comparisons, then fitting the final model under a corrected setting that MAE comparison never actually evaluated. Ukraine's own forecast is unchanged by this fix (it already had `yearly_seasonality=False` from the growth-cap rollout); the visible effect is in the other 30 countries - e.g. Germany's forecast changed from an oscillating 2.01%/2.20%/2.40%/2.18%/2.34%... pattern to a smooth 1.86%/1.94%/2.01%/2.08%/2.16%... trend. Verified: retrained all 31 models, confirmed live via `/forecast` for several countries, existing test suite passes.

**Checked specifically (2026-07-24): did this fix affect Türkiye's chosen model, since the caveat-vs-scenario decision was built on it?** `chosen_model` is still `"linear"` - it did not flip. But the reasoning behind that decision is now substantially undermined, not just technically confirmed: `best_prophet_mae` dropped from 0.0072671 to 0.0029411 - the seasonality bug had been making Prophet look ~2.5x worse than it really is for Türkiye. The gap that made switching to Prophet look like a bad trade (the "+0.44pp accuracy cost" central to that decision) has collapsed to **0.00145pp** - linear still wins, but by a hair, not decisively. The ~0.3pp scenario-differentiation signal from `test_scenarios_turkiye.py` is unaffected (that script already had `yearly_seasonality=False` applied before its results were reported), but the accuracy-cost side of the comparison it was weighed against was computed from the pre-fix `model_selection_log.json` and is now stale. **Not yet re-decided - this is a new finding, not a reversal**, surfaced by checking exactly what was asked rather than stopping at the literal "did the chosen model change" question.

**Result 1 (historical backtest, train <=2015, test 2016-2025) - not a valid test of the regressor, and that's itself the finding.** `conflict_active` is 0 for every row in the training window; 2022 is the first year it is ever 1, and that year falls entirely in the held-out test set. Prophet has zero training examples of the flag "on" to learn a coefficient from, so the fitted effect is essentially unidentified - MAE came out *worse* than baseline (0.12535 vs 0.12250, +2.3%), and `fixed_pred` barely reacts to 2022-2025 at all. This generalizes beyond this one test: **a regressor cannot be validated by backtesting against a regime the training data never contained.** Round 1's MAE comparison was meaningful because `spike_ratio` had genuine pre-2016 variation to fit against; this one isn't, structurally, for any single-conflict country's first occurrence. Worth remembering before trusting a similar backtest for the next flagged country.

**Result 2 (full 1980-2025 retrain, 15-year forecast) - the actual test that matters here, since the full training data now contains the 2022-2025 conflict years.** Both scenarios stay well-bounded, unlike baseline's unconstrained 111.4% by 2040:
- *Conflict continues* (flag=1 for the full horizon): plateaus around 34-36% of GDP for the whole forecast - below the 50% cap, in a plausible range given 2025's actual 39.6%.
- *Conflict ends* (flag=0 from 2026 on): drops to ~5-6% by 2040 - below Ukraine's own historical pre-war floor (~3-4%), a fast decline worth flagging rather than treating as precisely correct.

**Decision: split verdict, not a single accept/reject.**
1. **Growth cap: adopted, no open questions.** It does exactly what it was added for - bounds the forecast to a stated, defensible ceiling regardless of what the trend or any regressor does - and Result 2 confirms it holds once `yearly_seasonality` is off. Being built out to other flagged countries now (see step 5.1 below).
2. **Conflict-flag regressor: adopted, but its magnitude is a hand-set assumption, not a statistically fitted coefficient - stated explicitly rather than presented as more rigorously derived than it is.** The dataset contains exactly one real conflict occurrence (Ukraine 2022+, 4 data points). No amount of further backtesting or model tuning manufactures more signal than that; Result 1 shows precisely why a coefficient learned from one event can't be trusted the way `spike_ratio`'s coefficient could have been if round 1 had worked. This puts the conflict flag's magnitude in the same category as the scenario templates themselves (step 6): a deliberate, documented human judgment call about what "conflict continues" should mean quantitatively, not a number the data determined on its own. Direction (1) from round 1 (lowering `changepoint_prior_scale` further) remains untried and unnecessary for now, since the combination above already resolves the runaway-extrapolation problem this whole step exists to fix.

**6. Scenario forecasting**

Decided: a country is flagged for scenario treatment if its volatility (from the existing `calculate_volatility` function) is more than 2 standard deviations above the mean volatility across all 31 countries — a standard statistical definition of an outlier, not an arbitrary cutoff, and one that already correctly flags Türkiye using data already computed earlier in this project. Countries below this threshold keep the current single-line forecast; not every country needs scenario treatment. This flagging step runs on SIPRI spending volatility directly — it doesn't depend on GDELT, clustering, or embeddings at all, and already works today.

Ukraine and Türkiye are the two **founding validation cases** — hand-researched and hand-written specifically to ground-truth what a real conflict scenario and a real currency scenario should look like before anything gets automated. They are not the general pattern for every future flagged country. For any country flagged in the future, scenario construction is automated: that country's category — from step 4's *individual* review of its own flagged year(s), never a cluster-inherited label — selects a generic template, applied without per-country manual research:

- A **conflict** label gets the conflict template below.
- A **currency instability** label gets the currency template below.
- A **policy shift** label has no template yet — there's no validated example to design one from (see the Germany finding in step 4). This needs to be defined before any policy-shift-labeled country can reach this step; until then, treat it the same as "undetermined by GDELT."
- **"Undetermined by GDELT"** gets no automatic template. It needs the same kind of manual research Ukraine and Türkiye originally got, since automation has nothing reliable to act on.

**Clarified (2026-07-23): "undetermined" is a lack-of-investigation state, not a lack-of-automated-detection state - these are not the same thing, and conflating them was a real mistake caught before it got built.** The doubly-confirmed blind-spot finding (step 1/4) means neither GDELT nor `calculate_volatility` can *detect* Türkiye's currency crisis on their own - but that's a statement about our tools' coverage, not about whether the underlying cause is known. It is known: independently researched and confirmed the same way Ukraine's conflict was (real lira depreciation since 2018, a real historical anchor). Türkiye remains a founding, hand-verified validation case exactly like Ukraine, entitled to its currency-instability template - not "undetermined." **"Undetermined" is reserved specifically for a future country `calculate_volatility` flags that nobody has personally researched yet** - a genuine unknown-cause state, which currently has no live example (only Ukraine and Türkiye are flagged today, and both are researched).

**Türkiye scenario proof-of-concept (2026-07-23), `backend/test_scenarios_turkiye.py` - a real, unresolved tradeoff surfaced, not yet decided.** Mirroring how Ukraine's scenarios were proven out (`backend/test_scenarios_ukraine.py`) before touching `main.py`/the frontend. Three things checked that couldn't be assumed from Ukraine's precedent:
1. **`model_selection_log.json` has Türkiye's chosen production model as linear regression** (MAE 0.00293), decisively beating Prophet's best tested scale (MAE 0.00727) - the opposite of Ukraine, where Prophet was already the chosen model. Scenario capability (conditioning on a future assumption) is a Prophet-only mechanism, so building any scenario at all means deliberately using the worse-fitting model.
2. **No growth cap needed** - checked directly: historical max 4.30% of GDP (1982), 2018-2025 crisis years sit at 1.6%-2.6%, below that max. An explicit, evidence-based "no cap needed" decision (see the two-gate design above), not an omission.
3. **The backtest is structurally invalid, the same root cause as Ukraine round 1**: `currency_active` is 0 for every training-window row before 2016; the real crisis (2018+) falls entirely in the held-out test set, so baseline and regressor MAE came out identical (0.00294) - expected, not a finding.

**The tradeoff, stated explicitly rather than left implicit: switching Türkiye from linear regression to Prophet costs roughly +0.44pp of typical forecast error (0.00293 -> 0.00727 MAE), to gain a regressor whose actual scenario-differentiating effect is only ~0.3pp** (both scenarios inherit Türkiye's real, decades-long declining trend; the regressor adds a modest, roughly constant offset once the two flag paths diverge, nothing like Ukraine's tens-of-percentage-points effect). The accuracy cost and the scenario signal are the same order of magnitude - unlike Ukraine, where the growth cap fixed an actively wrong, unbounded number (correctness, not an accuracy tradeoff) and the conflict flag's effect dominated any model-choice noise. **Decided (2026-07-23): not worth making.** Paying 0.44pp of real, measured accuracy for ~0.3pp of scenario differentiation is a bad trade on the numbers alone, and presenting two named scenarios that thin would manufacture more apparent insight than actually exists, on a model already known to fit worse. Türkiye stays on its real production model (linear regression, unchanged, MAE 0.00293) - no override, no `test_scenarios_turkiye.py` mechanism shipped. Instead, `/forecast` attaches a qualitative caveat noting known currency instability since 2018 with future magnitude not reliably estimable, alongside the ordinary trend forecast every other unflagged country already gets. This is a distinct presentation format from Ukraine's `"scenario"` status (multiple named forecasts) - a single number, honestly labeled, not a fabricated choice between paths whose difference is smaller than the noise of picking a worse-fitting model to produce them. Ukraine's three scenarios (see above) remain approved and are being wired in separately; Türkiye's caveat is implemented now since it required no further validation step - unlike the scenario mechanism, it changes nothing about the underlying model.

**Design (2026-07-23, not yet implemented - `main.py`/frontend untouched):** a `status` field on the eventual `/forecast` response distinguishes three states - `"trend"` (unflagged, unchanged), `"scenario"` (flagged, researched, has a template - Ukraine today, Türkiye once its currency template is built the same hand-set-flag way as Ukraine's `conflict_active`), and `"undetermined"` (flagged, not yet researched). Growth-cap safety and scenario-research completeness are orthogonal axes and must be gated in sequence, not collapsed into one check - this was the key risk flagged before building: a country must first pass the existing growth-cap safety gate (a cap value or an explicit, deliberate "no cap needed" decision - never an absence defaulting to unsafe) before the research-status question is even asked. `"undetermined"`'s trend-forecast fallback is generated through that same already-capped model and the same cap-application code path already in `main.py` - never a second, separate uncapped path - so it can never silently bypass the cap. This composition means `"undetermined"` can only ever be reached by a country already confirmed numerically safe; it is strictly "safe, but not yet researched," never a route to an unsafe number.

Decided scenario templates, defined via the two founding cases but written generically enough to apply to any future country the category-matching step assigns to them:

- **Conflict template** (defined via Ukraine)
  - "Conflict continues at current intensity" — conflict flag held active for the full forecast horizon
  - "Conflict resolves within 3 years" — conflict flag active for years 1-3, inactive afterward, spending gradually reverting toward the pre-conflict trend
  - "Gradual de-escalation" — conflict flag steps down in intensity gradually, spending plateauing rather than fully reverting

- **Currency instability template** (defined via Türkiye)
  - "Currency instability continues" — continued high inflation/volatility at recent levels
  - "Currency stabilizes" — inflation/volatility reverts toward the country's own pre-crisis baseline within the forecast horizon

Each template is grounded in an already-established real event (the 2022 conflict start, the 2018 onset of currency instability), not an invented assumption.

**Resolved (2026-07-23): the Türkiye discrepancy above is not a bug and not mysterious - it's two different statistics catching two different kinds of anomaly.** `calculate_volatility` (std of year-over-year % change - a spikiness/dispersion measure) was never the method that originally identified Türkiye. That was an earlier Prophet `changepoint_prior_scale` sweep, where Türkiye stood out because *increasing* trend sensitivity made its forecast *worse*, unlike every other country tested - a different signature entirely. `calculate_volatility` was built afterward as a general-purpose tool and had never actually been re-validated against the Türkiye case until this check. Confirmed against all three of SIPRI's published series for Türkiye (`Share of GDP`: 0.1055; `Current US$`: 0.1533; `Constant 2024 US$`: 0.0868) - none read as an outlier under this statistic, because the lira's real, well-documented depreciation since 2018 is a sustained multi-year *drift*, not a single dramatic-outlier year, and std-of-pct-change is built to catch the latter, not the former. Full ranked list of all 31 countries confirms Ukraine (1.3796) is the only one above the 2-std-dev threshold (0.6122); Türkiye ranks 15th of 31 (0.1055), solidly mid-pack.

**This is now a doubly-confirmed detection blind spot for Türkiye specifically, worth its own line:** currency instability is invisible to *both* of this project's automated anomaly checks - GDELT event-detection (step 4's finding: Türkiye's 2018 `spike_ratio` is 0.77, actually below baseline - a currency crisis isn't a discrete reportable event, so it generates no event-volume signal at all) and now spending-volatility detection (this finding: a gradual drift produces low dispersion, so it doesn't cross a std-based threshold either). Both are real, correctly-implemented checks; the underlying phenomenon simply doesn't have either check's signature. This strengthens the case for the "undetermined by GDELT" branch already in the step 4/6 design - Türkiye's currency scenario in step 6 remains hand-researched precisely because no automated check would have surfaced it as needing scenario treatment in the first place. **Broader lesson for this whole pipeline:** each automated anomaly-detection method has its own specific blind spot, and a country passing one check is not evidence that it's genuinely unremarkable - only that it's unremarkable *by that particular check's definition of anomalous*.

**Automated pipeline rebuild + blind test (2026-07-24), `backend/scenario_pipeline.py` + `backend/blind_test_ukraine.py` - replaces the hand-set `conflict_active` flag with an end-to-end automated pipeline (detection -> GDELT-derived signal -> categorization -> template selection -> LLM-drafted magnitude), validated by running it blind on Ukraine.** Ukraine is the only country available for this: `calculate_volatility` organically flags exactly one country today, and it's also the one country with established ground truth to check an automated result against - using any other country would have required either borrowing prior GDELT findings (testing categorization/magnitude in isolation, not genuine detection) or loosening the volatility threshold with no independent justification (rejected outright, the same reasoning already applied elsewhere in this project against arbitrary threshold tuning). "Blind" means concretely: no hardcoded 2022 date, no country name or real calendar year ever sent to the categorization LLM (relabeled "Year 1/2/3..."), no reuse of any value from `test_regressor_ukraine*.py` or `test_scenarios_ukraine.py`, and the stage-2 threshold calibrated on the other 30 countries before Ukraine's own results are computed. Ground truth is consulted only after every stage has already run.

- **Stage 2 (new elevated-baseline signal, replacing `spike_ratio`):** `baseline_ratio` = a country's mention-share divided by its own long-run *median* share (a fixed reference point) rather than `spike_ratio`'s rolling trailing window, which was the documented problem being fixed - a rolling window gets pulled up by the anomaly's own recent years, causing the ratio to decay back toward 1.0 while the real anomaly is still ongoing. Threshold (mean + 2 std dev, the same convention `calculate_volatility` already uses) calibrated on the other 30 countries. Result: correctly identifies Ukraine's current episode as exactly **[2022, 2023, 2024, 2025]**, and additionally surfaces **1992, 2004, 2005, and 2014** as separate historical precedent episodes - not noise: independence-era Ukraine, the Orange Revolution, and Euromaidan/Crimea/the Donbas war's onset respectively, all real events the old hand-set flag simplified away because SIPRI *spending* barely moved in those years even though GDELT *event volume* clearly did. A genuine improvement in historical granularity over the flag it replaces.
- **Stage 3 (categorization, first attempt - failed, diagnosed, fixed):** an anonymized LLM call (Ollama/Mistral, no country/year revealed) first classified the 2022-2025 episode as `"other"`, not `"conflict"`. Cause: the prompt included `avg_goldstein` (0.31, 0.07, 0.19, 0.71 - all near zero/slightly positive), which the LLM read as "not conflictual enough," anchoring on exactly the feature step 1's finding already documented as diluted/unreliable at yearly granularity (Ukraine's real 2022 `avg_goldstein` reads as less negative than 2018's). Fixed by dropping `avg_goldstein` from the prompt, keeping only volume and tone - the features that finding already identified as reliable, a pre-existing general finding, not something derived from this test's outcome. Rerun once: correctly classified `"conflict"`, reasoning citing the 10.7x volume ratio and consistently negative tone.
- **Stage 5 (LLM-drafted magnitude, first attempt - failed, diagnosed, fixed):** with no numeric anchor for the country's actual spending level, the LLM produced an incoherent result (`CEILING_PERCENT_GDP: 6.0`, reasoning that visibly conflates the event-volume ratio with a GDP percentage via arithmetic that doesn't track its own logic). Fixed by adding the country's own last-observed spending (%GDP, real SIPRI data - structurally available for any flagged country, the same source `calculate_volatility` already reads, not Ukraine-specific knowledge) as a grounding anchor, plus an automatic coherence gate (a drafted ceiling that doesn't exceed current observed spending is definitionally not a ceiling, and now routes to an explicit "undetermined - requires manual review" state rather than being trusted at face value, mirroring the undetermined-by-GDELT pattern). Rerun once: `CEILING_PERCENT_GDP: 60`, `CONFIDENCE: moderate`, reasoning correctly comparing the current episode's severity against the four precedent episodes and appropriately discounting confidence for limited precedent count.
- **No paid-API fallback used or considered** - explicitly ruled out. Every fix was a local-model prompt/data correction, not a capability escalation.

**Result, compared against known ground truth only after every stage ran:** stages 1-4 landed exactly on the known answer (episode = 2022-2025, category = conflict) with zero manual input. Stage 5's ceiling (60% of GDP, moderate confidence) is in the right neighborhood as the hand-researched production value (50%, grounded in UK WW2 precedent) - same order of magnitude, same qualitative conclusion (a bounded wartime-economy ceiling, nowhere near the 100%+ runaway this project phase exists to fix) - but not a precise match, a real 10pp gap stated plainly rather than rounded away.

**Decisions (2026-07-24), both made explicitly rather than left as an implementation default:**

1. **Ukraine keeps its hand-researched 50% cap; stage 5's 60% does not override it.** The reason is about verification, not accuracy: 50% has a real, independently-checkable external anchor (UK WW2 defense-spending precedent, itself verified via web search - see the round 2 finding above). 60% has none - it's the LLM reasoning from GDELT's own event magnitude alone, with nothing outside that data to check it against, even at its own stated "moderate" confidence. A value with real outside verification should not be displaced by one without, regardless of how plausible the unverified number looks.
2. **Generalize, don't replace.** Stages 1-4 (detection, GDELT-derived signal, categorization, template selection) performed perfectly in the blind test and now run automatically for any future flagged country - real, earned trust from an honest end-to-end validation, not an assumption. Stage 5 also runs automatically, but its output is never presented with the same confidence as a hand-researched value: `train.py`'s `determine_cap()` always checks `GROWTH_CAPS` (hand-researched) first, and only falls back to the automated pipeline for a flagged country with no hand-set entry. Every cap now carries explicit provenance metadata - `source: "hand-researched"` (externally verified) vs. `source: "automated"` (GDELT-only, not independently cross-checked) plus a `confidence` level - persisted in `growth_caps.json` and surfaced directly in `/forecast`'s response (`cap_source`, `cap_confidence`, `cap_note`). An automated estimate and a hand-researched one must never look equally confident to a consumer of the API, and now structurally can't.

**Implementation:** `determine_cap()` now lives in `backend/scenario_pipeline.py` (not `train.py`), specifically so it's safely importable and independently testable - `train.py` has no `if __name__ == "__main__":` guard and runs its full training loop (refits all 31 countries, overwrites production artifacts) as top-level code on import, so it can't safely be imported just to reach one function. Verified directly: ran `determine_cap()` against Nigeria (not actually flagged, but exercising the automated fallback path end-to-end without touching real flagged-country data) - it correctly computed Nigeria's elevated episode, categorized it (`conflict`), and drafted a coherent 6% GDP ceiling, correctly above Nigeria's actual last-observed spending (0.91% GDP, 2025). Also verified live: retrained all 31 models (Ukraine's cap and behavior unchanged), confirmed `/forecast` now returns `cap_source`/`cap_confidence`/`cap_note` for Ukraine, confirmed Germany and Türkiye are unaffected, and the existing test suite still passes.
